# Контроль готовности этапа иммерсивной кампании

ООП-реализация КТ3, Java 17. Проверено на OpenJDK 17.0.18 и 23.0.2. Сборка через `javac`, запуск через `java` — средства JDK. Для JSON используется Gson 2.13.2, для тестов — JUnit 5.11.4.

## Структура

```text
src/java/
├── Main.java     точка входа
├── core/         сущности, правила, алгоритмы и сценарии
├── main/         чтение JSON, командная строка и вывод
├── tests/        проверки JUnit
├── data/         пример данных и эталон результата Python
└── README.md
```

`lib/` содержит локальные JAR библиотек, `out/` — результат компиляции и тестирования. Обе папки исключены из Git.

## Подготовка и запуск

Нужен JDK 17 или новее. Из корня репозитория перейдите в `src/java`, создайте папки и один раз скачайте Gson:

```sh
cd src/java
java -version
mkdir -p lib out
curl -fL https://repo.maven.apache.org/maven2/com/google/code/gson/gson/2.13.2/gson-2.13.2.jar -o lib/gson-2.13.2.jar
```

Сборка и запуск на macOS/Linux:

```sh
javac --release 17 -encoding UTF-8 -cp lib/gson-2.13.2.jar -d out Main.java core/*.java main/*.java
java -cp 'out:lib/gson-2.13.2.jar:data' Main demo --order O1 --as-of 2026-10-31
```

Без аргументов `Main` выполняет демонстрацию для O1 на текущую дату. Для повторения результата явно передавайте `--as-of`.

Все четыре операции после сборки:

```sh
java -cp 'out:lib/gson-2.13.2.jar:data' Main brief --order O2
java -cp 'out:lib/gson-2.13.2.jar:data' Main readiness --stage S1
java -cp 'out:lib/gson-2.13.2.jar:data' Main overdue --as-of 2026-10-31
java -cp 'out:lib/gson-2.13.2.jar:data' Main overdue --order O1 --as-of 2026-10-31
java -cp 'out:lib/gson-2.13.2.jar:data' Main summary --order O1 --as-of 2026-10-31
java -cp 'out:lib/gson-2.13.2.jar:data' Main --data ../sample_data.json --json demo --order O1 --as-of 2026-10-31
```

Файлы данных не изменяются. Код завершения 0 — выполненная проверка, в том числе отрицательный бизнес-результат; код 2 — ошибка аргументов или входных данных. В Windows при запуске `java` между путями в `-cp` используется `;` вместо `:`.

## IntelliJ IDEA

1. Выберите JDK 17 или новее для Java-модуля.
2. Отметьте `src/java` как **Sources Root**, `src/java/tests` как **Test Sources Root**, `src/java/data` как **Resources Root**. Папки `lib` и `out` исключите из исходников.
3. Добавьте `lib/gson-2.13.2.jar` в зависимости модуля. Для тестов также добавьте JUnit из раздела «Проверки» с областью **Test**.
4. Откройте `Main.java` и запустите метод `main`. Для воспроизводимой демонстрации задайте аргументы `demo --order O1 --as-of 2026-10-31`.

## Организация логики

`core` использует только стандартную библиотеку Java: 11 сущностей логической модели, `ReworkTask`, `CampaignData`, правила `BriefRule`, сервисы проверки и сценарии `CampaignService`. Закрытые поля и `List.copyOf` защищают данные от изменения. `OrderMember` и `TaskMaterial` выражают связи многие-ко-многим.

`main` зависит от `core`, читает JSON и форматирует результаты. `Main.java` создаёт зависимости и выбирает сценарий. Направление зависимостей сохраняет отделение бизнес-правил от ввода и вывода при двух простых пакетах.

`ReworkTask` наследует `Task` и дополнительно проверяет принадлежность исходного замечания тому же этапу. Метод вызывается полиморфно при загрузке списка задач. `BriefRule` имеет три реализации, `ResultPresenter` — текстовую и JSON-реализацию. Оба интерфейса используются в рабочих сценариях.

Алгоритмы сохранены относительно Python: готовность этапа — O(N²), просрочки с сортировкой и бинарным поиском — O(N log N); дополнительная память O(N). N — суммарное число записей; оценка относится к операции после загрузки. Последняя версия определяется по числовому `number`, просрочка — строго `deadline < as_of`.

Команды принимают только свои параметры: `brief` — `--order`, `readiness` — `--stage`, `overdue`, `summary` и `demo` — `--order` и `--as-of`. Общие параметры `--data` и `--json` доступны всем командам. Несовместимый параметр возвращает код 2 вместо игнорирования.

Повторяющиеся имена полей JSON отклоняются до построения модели, в том числе во вложенных объектах и при экранировании имени через Unicode. Сообщение содержит имя поля и путь до него. Одинаковые имена в разных объектах допустимы.

При создании снимка один раз строятся `Map` для поиска сущностей по ID и `Set` сотрудников для каждого заказа. Проверка контекста использует эти индексы, сохраняя порядок исходных списков и прежние сообщения о неверных связях. Построение индексов и проверка связей занимают в среднем O(N) времени и O(N) памяти; оценки самих двух алгоритмов выше сохраняются.

## Проверки

Из `src/java` один раз скачайте автономный запуск JUnit:

```sh
curl -fL https://repo.maven.apache.org/maven2/org/junit/platform/junit-platform-console-standalone/1.11.4/junit-platform-console-standalone-1.11.4.jar -o lib/junit-platform-console-standalone-1.11.4.jar
```

После сборки основной программы выполните:

```sh
mkdir -p out/tests
javac --release 17 -encoding UTF-8 -cp 'out:lib/gson-2.13.2.jar:lib/junit-platform-console-standalone-1.11.4.jar' -d out/tests tests/*.java
java -jar lib/junit-platform-console-standalone-1.11.4.jar execute --class-path 'out:out/tests:lib/gson-2.13.2.jar:data' --select-class ContractTest --reports-dir out/test-results --disable-banner --details summary
```

Проверяются 35 случаев: эталон Python, последняя версия, граница срока, закрытые заказы, контекст доработки, целостность данных, ошибки брифа, дополнительные поля JSON, Unicode, внедрение нового правила, допустимые параметры команд, повторные имена полей JSON, строгий синтаксис и отсутствие повторных обходов задач при проверке связей. Результаты сохраняются в `out/test-results`.

Для сравнения с процедурной версией:

```sh
python3 ../main.py --json demo --order O1 --as-of 2026-10-31
java -cp 'out:lib/gson-2.13.2.jar:data' Main --json demo --order O1 --as-of 2026-10-31
```

Эталон `data/expected_demo.json` получен процедурной программой на том же наборе данных и той же дате. При сравнении JSON пробелы и порядок ключей не учитываются, значения и порядок элементов массивов должны совпасть.
