# 3 СРЕДА РАЗРАБОТКИ И СИСТЕМА КОНТРОЛЯ ВЕРСИЙ

## 3.1 Среда разработки

Для работы с проектом выбрана IntelliJ IDEA компании JetBrains. Она подходит для разработки Java, навигации по коду, отладки и работы с Git. Для Python предусмотрен плагин; его наличие и настройки интерпретатора необходимо проверить в установленной среде. Возможности среды рассматриваются в материалах выпуска IntelliJ IDEA 2024.3 [6].

## 3.2 Языки программирования

Процедурную реализацию планируется выполнить на Python с использованием списков и словарей для представления заказов, задач и согласований. Стандартная библиотека предоставляет средства работы с датами и JSON, поэтому первую реализацию можно подготовить без внешних зависимостей. Учебным источником по Python служит пособие Д. Ю. Федорова [7]. Минимальная целевая версия проекта – Python 3.12.

Объектно-ориентированную реализацию планируется выполнить на Java с целевой совместимостью Java 17. Предполагаются классы заказа, задачи, материала и согласования, перечисления статусов и отдельный сервис проверки правил перехода. Общие принципы объектно-ориентированного программирования рассматриваются в пособии А. Ф. Тузовского [8]. Алгоритмы обеих реализаций должны получать сопоставимые данные и возвращать одинаковые результаты.

Основные правила проверки будут отделены от пользовательского интерфейса. Это позволяет сначала отработать их в консольных программах, а затем при необходимости подключить веб-интерфейс. Создание графических иммерсивных материалов не является задачей этих реализаций.

## 3.3 Система управления базами данных

Для последующего хранения данных выбрана PostgreSQL 17. У заказа есть клиент и этапы, у этапа – задачи и версии материалов, а у решения клиента – ссылка на согласуемую версию. Такие связи удобно представить реляционной моделью и защищать ограничениями целостности. PostgreSQL поддерживает внешние ключи и транзакции [9].

## 3.4 Система контроля версий

Используется распределённая система Git. Удалённый репозиторий проекта practice размещён на GitHub по адресу https://github.com/kokuyouu/practice. Система сохраняет историю изменений и позволяет сравнивать версии файлов; для изучения инструментов разработки и контроля версий используется подборка материалов Selectel [10].

В README.md указаны тема практики, автор и назначение каталогов. Каталог docs содержит разделы отчёта, список источников, перевод и итоговый документ. Каталог cmd предназначен для запускаемых программ, internal – для внутреннего кода, configs – для настроек, scripts – для вспомогательных команд. Существующая структура верхнего уровня сохранена. Хранение конфигурации вместе с кодом соответствует подходу к описанию инфраструктуры, представленному А. Алексеевым [17].
