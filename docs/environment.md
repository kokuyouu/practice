# 3 СРЕДА РАЗРАБОТКИ И СИСТЕМА КОНТРОЛЯ ВЕРСИЙ

## 3.1 Среда разработки

Для работы с проектом выбрана IntelliJ IDEA компании JetBrains. Она подходит для разработки Java, навигации по коду, отладки и работы с Git. Для Python предусмотрен плагин; его наличие и настройки интерпретатора необходимо проверить в установленной среде. Возможности среды рассматриваются в материалах выпуска IntelliJ IDEA 2024.3 [6]. Выбор соответствует тому, что локальный репозиторий уже размещён в каталоге IdeaProjects.

Программы проверки запуска не требуют дополнительных библиотек. Файл cmd/hello.py выводит версию Python, а internal/Hello.java – версию Java. Они позволяют проверить базовую доступность интерпретатора и JDK перед реализацией алгоритмов. Это проверка запуска, а не готовая система управления агентством.

## 3.2 Языки программирования

Процедурная реализация КТ2 выполнена на Python 3.13.2. Используются функции и стандартные структуры данных list, dict, tuple и set, без собственных классов. Стандартная библиотека обеспечивает работу с JSON, датами, аргументами командной строки и бинарным поиском. Внешние зависимости не требуются. Учебным источником по Python служит пособие Д. Ю. Федорова [7]. Минимальная поддерживаемая версия – Python 3.12.

Объектно-ориентированную реализацию планируется выполнить на Java с целевой совместимостью Java 17. Предполагаются классы заказа, задачи, материала и согласования, перечисления статусов и отдельный сервис проверки правил перехода. Общие принципы объектно-ориентированного программирования рассматриваются в пособии А. Ф. Тузовского [8]. Алгоритмы обеих реализаций должны получать сопоставимые данные и возвращать одинаковые результаты.

Правила проверки отделены от пользовательского интерфейса. Операции реализованы в src/operations.py, загрузка и проверка связей – в src/data.py, консольные команды – в src/main.py. В дальнейшем интерфейс можно расширять при сохранении бизнес-правил. Создание графических иммерсивных материалов не является задачей программного ядра учёта.

## 3.3 Система управления базами данных

Для последующего хранения данных выбрана PostgreSQL 17. У заказа есть клиент и этапы, у этапа – задачи и версии материалов, а у решения клиента – ссылка на согласуемую версию. Такие связи удобно представить реляционной моделью и защищать ограничениями целостности. PostgreSQL поддерживает внешние ключи и транзакции [9].

На исследовательском этапе сформирован перечень будущих сущностей. Создание таблиц, настройка подключений из Python и Java и проверка запросов будут выполнены на проектном этапе. Наличие выбранной СУБД не означает, что база уже развёрнута или физическая модель реализована.

## 3.4 Система контроля версий

Используется распределённая система Git. Удалённый репозиторий проекта practice размещён на GitHub по адресу https://github.com/kokuyouu/practice. Система сохраняет историю изменений и позволяет сравнивать версии файлов; для изучения инструментов разработки и контроля версий используется подборка материалов Selectel [10].

В README.md указаны тема практики, автор и структура проекта. Каталог docs содержит разделы отчёта, источники и перевод; src – процедурную программу КТ2 и инструкцию запуска; models – диаграммы. Каталоги cmd и internal содержат проверки окружения, configs – настройки, scripts – вспомогательные команды. Хранение конфигурации с кодом соответствует подходу А. Алексеева [17].
